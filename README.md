# cc-clinic-lab · 临床试验访视采集台

数据工程产品线基线。题号前缀 `clinic-*`，默认端口 **7600**。

## 技术栈

- 后端：CherryPy + SQLite
- 前端：原生 JS SPA（顶栏薄荷绿丝带导航）
- 会话：itsdangerous 签名 Cookie
- 测试：pytest + httpx（依赖已列入 requirements）

## 登录

- 地址：`http://127.0.0.1:7600/login`
- 账号：`admin` / `123456`

## 页面

| 页面 | 能力 |
|------|------|
| 试验中心 | 中心登记、启停/观察、配额、方案版本生效 |
| 访视批次 | 开批、模拟抓取、追加访视行、合格入库、收齐/关闭 |
| 字段质控 | 按批/全量扫描、发现关闭/重开 |
| 缺口补采 | 排队、分片上限闸、执行成功/失败、失败重试 |
| 访视对账 | 缺口/发现/补采对照、中心矩阵、分片摘要、审计 |
| 台参数 | 设置读写（只展分片上限口径） |

## 分片上限（甲侧 · 旁路账册）

- 分片上限钉进旁路账册表 `shard_cap_ledger`，以业务键 `backfill_shard_cap` +
  字段指纹 + 版本落库；读侧只认账册，不回刷、不回落到台参数。
- 台参数只展「分片上限口径」，不承载可写上限值；写入口在缺口补采页的
  「分片上限闸」，一次写完，带版本 CAS 串行（两名值班同时写、后写者收版本冲突）。
- 补采闸按「并发分片数 × 每片上限」择最低有空位的分片；全满即拦超额补采。
  账册未落库或字段指纹与库表对不上，同样拦截。
- 失败任务只能走「重试排队」，不能靠反复点排队新增任务，避免把队列拖进死循环。
- 缺口补采页亮上限徽标与分片并发数；访视批次列表、对账矩阵按同一口径展示。
- 乙侧（双写两轨 + 过期档只读归档）为未择定骨架，已清除，只保留甲侧命运。

## 主链

中心 → 访视批次抓取 → 质控发现 → 缺口补采 → 对账报告；设置与审计贯穿写操作。

## 本地

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pytest
python run.py
```

Docker：`docker compose up -d --build`，健康检查打 `/login`。
